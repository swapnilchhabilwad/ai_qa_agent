# AI QA Agent: Technical Framework Documentation

## 1. Overview
The **AI QA Agent** is a context-aware test generation framework designed to transform Product Requirement Documents (PRDs) into exhaustive, professional-grade test suites. Unlike simple prompt-based generators, this agent uses **Retrieval-Augmented Generation (RAG)** and **Persistent Memory** to perform intelligent impact analysis and cross-document validation.

---

## 2. Core Architecture
The system is built as a pipeline consisting of five major phases:

### Phase 1: Data Ingestion & Indexing
- **Loaders (`utils/loader.py`)**: Support for `.txt` and `.pdf` files.
- **Chunking (`utils/chunking.py`)**: Large documents are split into smaller semantic chunks to fit within LLM context windows.
- **Vector Store (`utils/vector_store.py`)**: Uses **FAISS** and **OpenAI Embeddings** to index chunks. This allows the agent to "search" the PRD for relevant context based on a query.

### Phase 2: Requirement Analysis (`agents/analyzer.py`)
- The agent retrieves the top 20 most relevant chunks from the PRD.
- It summarizes these chunks into a structured **Feature Analysis** (Requirements, Rules, Constraints).

### Phase 3: Impact Analysis (`agents/analyzer.py` + `utils/memory.py`)
- **MemoryStore**: A JSON-based persistence layer (`data/system_memory.json`).
- The agent compares the *new* feature analysis against *historically analyzed* features from other PRDs.
- **Goal**: Identify if the new changes "break" or "modify" existing functionality (Regression detection).

### Phase 4: Test Case Generation (`agents/test_generator.py`)
- The agent uses a sophisticated multi-pass strategy to generate tests across **21 categories** (Smoke, API, Security, Boundary, UI, etc.).
- It performs "Self-Correction": It evaluates its own coverage and iterates until it hits a high coverage score.

### Phase 5: Export & Tracking
- **Exporter (`utils/exporter.py`)**: Converts AI responses into structured CSV files.
- **Usage Tracker (`utils/usage_tracker.py`)**: Records every token used and calculates the USD cost in real-time.

## 4. Usage Modes

### Mode 1: The CLI (`main.py`)
Used for quick, single-file generation from the terminal.
```powershell
python main.py --project ProjectName --file_path "path/to/prd.txt"
```

### Mode 2: The API (`app.py`)
Used for web integrations or interactive testing via a browser.
- **Start Command**: `python app.py`
- **Interface**: Open `http://localhost:8000/docs` to see the interactive Swagger UI.
- **Endpoints**:
  - `POST /generate-tests`: Trigger a full generation run.
  - `GET /usage`: Check real-time billing and token status.

## 5. Technical Design Decisions
- **Modularity**: Every component (Memory, Usage, Agent) is isolated, making it easy to swap OpenAI for another LLM later.
- **Statefulness**: The `MemoryStore` ensures that the agent "remembers" what it tested yesterday, preventing redundant work.
- **Cost Control**: The `usage_tracker` provides a safety net by tracking costs per session and per day.
- **Resilience**: The system includes a `local_fallback` that can generate basic tests even if the AI API is unreachable.
